# 服务端稳定性扫描与改造

本轮针对 HTTP 事件循环阻塞和后台工作资源失控进行代码扫描、隔离改造和故障测试。这是一次具体的稳定性加固，不代表对所有部署环境作出可用性保证。

## 已处理

| 路径 | 原风险 | 当前处理 |
| --- | --- | --- |
| 主机资源轮询 | 同步系统查询影响所有 HTTP 请求；多标签页重复采样 | 独立 Worker；合并并发采样，结果缓存 1 秒；进程内存信息仍由主线程采集，避免误报 Worker 堆 |
| CC Switch 同步 | 定时同步 SQLite 查询阻塞；失败可能覆盖成功结果 | Worker 查询；同一来源合并并发同步；读取失败保留上次成功快照，后续轮询重试 |
| Claude 历史读取、分支、回退 | 整份 JSONL 主线程解析、重写 | Worker 解析与分支写入；相同文件的缓存加载合并；128 MiB 文件预检上限；解析 Worker 堆上限 256 MiB |
| 会话全文搜索 | SQLite FTS 索引、查询和删除在主线程执行 | 独立串行 Worker；传输前只保留有界的用户/助手文本；分批让出事件循环；不复制工具输出；拒绝旧版本覆盖新索引 |
| CLI 发现与版本探测 | 同步目录扫描；版本探测并发无界 | 扫描在 Worker；异步版本探测全局并发 4、排队 32、单次默认 5 秒超时、64 KiB 输出上限 |
| Windows 进程树结束 | 同步 taskkill 阻塞 | 异步执行，5 秒超时；完成或失败后才结束直接子进程，保留原顺序 |
| 本地运行设置 | 同步读盘；并发写入互相覆盖 | 常用读取走内存；更新异步读取并串行原子写入；供应商文件写入同样串行 |
| 服务关闭 | Worker 未清理；HTTP 尚未关闭就取消强退计时 | 拒绝新后台任务、清理等待任务、结束 Worker；HTTP 关闭完成前保留 5 秒退出兜底 |

## 后台工作约束

- 不同工作类别使用独立通道；每个通道只执行一个任务，包含执行中的任务最多 16 个。
- 排队和执行合计最多 30 秒；超时返回 504，容量不足、关闭或 Worker 故障返回 503。失败后不回落到主线程执行。
- 活跃和待结束 Worker 总数最多 8 个，避免阻塞系统调用导致旧 Worker 迟迟不退出时无限新建线程。
- 超时或崩溃会拒绝受影响通道的所有任务；下一次请求按需重建，不自动重放可能已经产生副作用的操作。
- 版本探测子进程由主线程异步管理，避免 Worker 重启时丢失子进程的超时计时器。
- 每 30 秒检查事件循环延迟；最大延迟达到 500 ms 时输出 `[health]` 警告。日志不包含请求内容或凭据。

## 验证和边界

自动测试覆盖 HTTP 在后台同步阻塞期间仍响应、队列满、超时后恢复、Worker 崩溃、传输失败、关闭、异步结束进程顺序、后台全文搜索及配置同步失败后的恢复。测试使用临时文件和独立临时端口，不接管正在运行的服务。

本轮验证结果：全量回归 1035 项通过、2 项跳过；最后的 Worker 生命周期改动另有针对性回归通过；TypeScript、服务端编译和 Vite 构建通过；编译产物中的主机采样与 SQLite 搜索 Worker 实际启动检查通过。

本轮在原生 Linux 上验证。Windows/macOS 分支做了静态检查与可替代的顺序测试，仍需对应系统的实际运行验证。

以下开销仍存在，不能宣称事件循环永远不会停顿：

- HTTP/WS 的 JSON 编解码、摘要快照生成、Agent 协议消息解析仍在主线程；超大消息或极大会话库可能产生 CPU 峰值。快照已有短时缓存、广播合并和慢客户端积压限制，后续应结合延迟日志和真实负载制定消息大小与分页策略。
- 进程锁的排他创建、启动时安装辅助文件等生命周期操作仍使用同步文件 API；它们与高频 HTTP/轮询路径区分。数据目录位于缓慢网络文件系统时，启动/锁更新仍可能变慢。
- 第三方 Agent 请求、原生数据库、文件系统和外部进程的故障无法靠线程隔离消除；隔离保障的是慢工作不会直接占用 HTTP 事件循环，接口自身仍可能超时。
- 文件大小预检与 Worker 堆上限不等同于进程总内存硬限额；文件在读取期间增长、结构化克隆和 native 内存仍需依靠部署层的资源监控。

编译后的后端需要重启后生效；构建本身不会重启已有服务。
