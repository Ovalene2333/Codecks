# 通用 API 与 Deck 宿主的边界

本说明记录核心库抽取前的设计结论；当前实现仍由 Deck 托管，尚未发布独立 SDK、`/v1` 路由或 daemon。

## 当前四操作契约

新关系以 create/send/receive/del 为默认流程；以下原 create/send/tasks/result 的抽库评估为历史背景，不再约束新默认入口。

通信层负责持久 inbox、单一消费状态、请求重放、结构化结果/失败消息以及可恢复删除；receive 和自动批量投递必须经同一仲裁。消息持久受理、工具领取/原生投递、执行完成与用户已读是四个不同事实，不声称端到端 exactly-once。

宿主仍负责自动续跑预算、用户暂停/继续、静默任务、UI 阅读状态、通知订阅、worktree 和外部 wake。系统通知不得成为新任务结果的第二条自动交付链路。旧关系按原协议排空，不全量搬历史消息；新关系 protocol=2 可识别，不能混用两套消费者。

## 历史默认调用成本

通用 Agent 的日常流程只需要 create、send、list/tasks、result。创建时默认不枚举模型，不传每个配置；发送时默认使用来源绑定。任务结束、最终文本可用、消息受理/送达和用户已读分别表达，不能靠 Agent 记住额外 `--final` 来保证可靠性。

高级配置须可由 API 读取，UI 只做配置客户端。wait、回执查询与批量领取按需使用，不加入每次必须执行的流程。skill 入口仅保留常用语义；模式细节由 CLI help 按需提供。

## 后续核心库应保留的语义

| 核心语义 | 最小信息 |
| --- | --- |
| 会话引用与来源关系 | agentId/threadId、稳定引用、来源与目标 |
| 创建与能力描述 | 请求配置、适配器确认值、默认/原生来源；可用消息模式和配置项 |
| 持久消息 | 投递 ID、有效模式、排队/发送/送达/失败、可重试性 |
| 回合结果 | turnId、执行状态、等待原因、非空最终文本/空答复/待同步；只读可重复 |
| 查询与生命周期 | 按来源查询、stop/delete；可选有界等待 |

按回合确认或增量游标可供 SDK 选择；Deck 的共享未读标记不是通用消息阅读回执。抽库时不得将 collect 强制放进 Agent 工作流。

## 留给宿主的策略

Deck 的主会话保护、禁止嵌套 create、detached 提示模板与静默默认、通知订阅/合并/限频、未读 UI、权限允许集合、worktree、wake/watcher、别名格式和注入提示词属于宿主。

抽库时主会话应由宿主给出 protected 属性，而不是核心通过“不是任何关系的目标”推导。detached 保留为 Deck 兼容预设。各工具的可配置选项最终由适配器声明，不能把某几家 CLI 的权限枚举或高低排序当成通用 API。

本轮通知扩展保留在 Deck：结果/等待默认关，普通失败默认开，detached 失败默认关。通知正文历史有保留范围，按 taskId + turnId + kind 的紧凑去重键持续保留；不依赖时间戳防重。系统通知不得与 Agent 主动消息合并。

## 明确保留到抽库阶段的工作

- 独立核心模块与 HostPort、版本化路由、统一机器错误码。
- adapter 声明 opaque 配置项；不再在通用层固定原生权限枚举。
- 显式会话级凭据与管理凭据分离。当前同一 Deck token 是可信本机模型，不是防恶意 Agent 的授权边界。
- 列表增量游标、按回合 ack，以及清晰的多读者语义。
- 调用方提供的幂等键：作用域为调用方 + 键，保留期限写入契约。当前紧凑投递回执仅保留 Deck 内部派生 ID 的去重，`send --to` 尚无调用方幂等键，不承诺无限期对外幂等。
- 初始投递状态与 AskRecord 解耦后，再考虑内部回执 TTL 删除。当前只清除旧正文/图片；不承诺总元数据体积恒定。

原生会话同时只由一个 adapter 宿主管理。未来宿主可以是 Deck 或 headless runner，部署形态不必固定为 daemon。

## 本轮默认选择

权限默认值与允许集合由用户维护；允许集合可以为空，表示 Agent 不能自行选择。cwd 保持用户选择自由；workspace-write 的实际工作区随目标 cwd 改变，目录限制由未来宿主策略提供。本轮不引入新的权限框架，也不宣称上述可信本机检查具有安全隔离能力。
