# Codecks 前端设计系统

Codecks 使用 MUI Material 提供基础交互、可访问性和响应式行为，在其上维护一层紧凑的控制台主题。Google Cloud 是交互层级参考，Cloudflare Dashboard 是信息密度参考；不要逐页复制它们的样式。

## 代码边界

- `src/design-system/theme.tsx` 是新组件颜色、字号、圆角、间距和 MUI component override 的唯一来源，并向旧页面输出兼容 CSS 变量。尚未迁移的专用语义变量暂时保留在 `tokens.css`，迁移后删除。
- `src/design-system/components.tsx` 暴露业务页面可用的基础控件。新增页面优先使用这里的 `AppButton`、`AppIconButton`、`TextInput`、`SelectField` 和模式选择组件。
- `src/design-system/design-system.css` 只负责组件组合的稳定几何与响应式布局，不重新定义主题颜色。
- `src/ui.tsx` 保留弹窗、确认框、抽屉和状态等跨功能组件；这些组件应逐步改为调用设计系统，而不是复制实现。
- 功能组件不要直接从 `@mui/material` 导入。确实缺少控件时，先在设计系统中定义项目默认值再导出。

## 视觉规则

- 界面保持工作台密度：桌面控件通常为 36-40px，高频列表以边框和留白分区，避免把每个区域做成浮动卡片。
- 圆角只使用 4px、6px、8px 三档；弹窗、抽屉和真正独立的内容项才使用容器边框。
- Geist 是界面字体，Geist Mono 只用于路径、命令、标识符和数字对齐场景。
- 图标统一使用 Lucide。不要和 MUI Icons 或手绘 SVG 混用。
- 蓝色只表示主要操作、选中和焦点；运行、等待、危险等状态使用对应语义色。
- 不添加装饰渐变、胶囊标签、嵌套卡片或仅用于“丰富画面”的信息块。

## 实现规则

- 不在业务组件中硬编码颜色、阴影或圆角；需要新语义时先扩展主题。
- `sx` 只用于无法由组件组合表达的一次性布局，不用于颜色和组件视觉变体。
- 新增按钮、输入框、选择框、弹窗和模式选择时，不直接写裸 HTML 控件。现存裸控件属于迁移范围，不作为新代码范例。
- 熟悉的纯图标操作必须有 `aria-label`；语义不明显时同时提供 tooltip。
- 手机宽度下，主要业务弹窗使用全屏布局；简单确认框保持紧凑。交互不能只在 hover 时出现。
- 每个视觉改动至少检查一个桌面视口和一个手机视口，并覆盖实际交互状态；涉及主题时同时检查明暗模式。

## 迁移顺序

设计系统采用渐进迁移，功能行为不随视觉迁移改变：

1. 公共弹窗、表单、按钮和模式选择。
2. 工具中心、任务抽屉和设置页面。
3. 侧栏、会话顶栏和输入区。
4. 时间线、工具调用、审批和文件 diff。
5. 删除已无引用的旧 CSS 规则与重复 token。

每批迁移应独立提交，并在仓库根目录执行测试和构建。前端验证按 `skills/frontend-testing-debugging/SKILL.md` 检查桌面、手机、控制台错误和核心交互。
